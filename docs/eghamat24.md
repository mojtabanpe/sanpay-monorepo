# اتصال اقامت۲۴

هتل و پرواز فقط با هدر `Client-Token` به API متصل می‌شوند. مقدار توکن یک رشتهٔ opaque است: کل مقدار ارسالی تأمین‌کننده باید حفظ شود و نباید قسمت URL یا خط تیره از آن حذف شود. `Auth-Token` و توکن پنل آژانس ارسال نمی‌شوند.

## تنظیمات محلی

- `GRS_MODE=live`
- `GRS_URL=https://hotel-test-01.denv.ir`
- `GRS_CLIENT_TOKEN` یا `GRS_CLIENT_TOKEN_BASE64`
- `FLIGHT_MODE=live`
- `FLIGHT_URL=https://gateway-test-01.denv.ir/flight`
- `FLIGHT_CLIENT_TOKEN` یا `FLIGHT_CLIENT_TOKEN_BASE64`
- `FLIGHT_CURRENCY=IRR` با تأیید کاربر

متغیرهای دارای پسوند `BASE64` اولویت دارند؛ در اجرای Nx از تغییر کاراکترهای `$` در توکن جلوگیری می‌کنند. این صرفاً کدگذاری است، نه رمزنگاری. مقادیر واقعی فقط در `.env` گیت‌ایگنورشده قرار دارند. پس از تغییر تنظیمات، API را دوباره اجرا کنید.

## رفتار هتل

`GrsHttpClient` با `GRS_MODE=live` جایگزین ماک می‌شود. تقسیم شهرها همچنان همان قاعدهٔ پروژه است: مشهد از اقامت۲۴ و سایر شهرها از هتل‌یار. `EGHAMAT24_CITIES` فهرست شهرهای اقامت۲۴ را تغییر می‌دهد.

فهرست شهرها، هتل‌ها و پیشنهادها با `page` و `count` تا `total` دریافت می‌شوند. محیط تست فعلی پارامتر قدیمی `offset` مستندات را نادیده می‌گیرد. خطای صفحه‌بندی، شبکه یا خطای داخل پاسخ HTTP 200 به دادهٔ نمونه یا فهرست خالی تبدیل نمی‌شود.

نرخ‌نامه‌های تودرتوی پاسخ واقعی، ظرفیت اتاق و `board_type` نگاشت می‌شوند. هزینه فقط برای شب‌های بازهٔ `[check_in, check_out)` محاسبه می‌شود؛ سرویس available-rooms ممکن است روز خروج را هم برگرداند. نرخ ناقص یا تکراری و ظرفیت نامعتبر قابل عرضه نیست. ریال در لایهٔ نگاشت به تومان تبدیل می‌شود.

## بررسی

- `pnpm nx run api:test-eghamat24`
- `pnpm nx run api:test-flights`
- `pnpm nx run api:check-eghamat24` — اتصال واقعی با درخواست‌های GET و اطمینان از نبود Auth-Token
- `pnpm nx run-many -t build lint -p api`

مسیرهای رزرو، تأیید و کنسلی مطابق قرارداد وب‌سرویس متصل‌اند، اما در بررسی واقعی رزرو، صدور بلیت یا پرداخت اجرا نمی‌شود. درخواست نوشتنی خودکار تکرار نمی‌شود. تست اتصال خواندن، تأیید عملکرد تراکنش واقعی نیست.

## محیط‌ها و پشتیبانی

این اطلاعات را اقامت۲۴ برای شرکت جهان صنعت پویا سیرجان صادر کرده است.

| چیز | آدرس |
| --- | --- |
| وب‌سرویس هتل | `https://hotel-test-01.denv.ir` |
| پنل داشبورد تست | `https://app.hotel-test-01.denv.ir/login` |
| وب‌سرویس پرواز | `https://gateway-test-01.denv.ir/flight` |

- **هر سه فقط از داخل ایران باز هستند.** از بیرون، اتصال TLS وسط دست‌دادن قطع می‌شود (`Connection reset by peer`)، مثل محیط دموی هتل‌یار. پس هر چک اتصال باید روی یک شبکهٔ ایرانی اجرا شود.
- پشتیبانی فنی: پیام‌رسان **بله**، شناسهٔ `grs_technical_support`.
- نام کاربری پنل تست یک شمارهٔ موبایل است و رمزش جداگانه داده شده. هیچ‌کدام در کد استفاده نمی‌شوند و فقط برای دیدن رزروها از سمت اقامت۲۴ لازم‌اند. توکن و رمز پنل فقط در `.env` و مدیر رمز تیم می‌مانند، نه در گیت.

## نکته‌های API که در کد منعکس شده‌اند

- **احراز هویت** فقط هدر ثابت `Client-Token` است: نه login، نه session، نه انقضا؛ برخلاف هتل‌یار منطق تازه‌سازی سشن لازم نیست. خود API اما REST واقعی است و کد وضعیت معنی دارد (۴۰۳ توکن نامعتبر، ۴۲۲ خطای اعتبارسنجی).
- **خطای موجودی با HTTP 200 برمی‌گردد** و فقط در `errors[]` دیده می‌شود؛ `GrsHttpClient` هر دو را بررسی می‌کند.
- **قیمت‌ها ریال‌اند** و کل صنعت‌پی تومان است؛ تبدیل فقط در `eghamat24.mapper.ts` (`rialToToman`) انجام می‌شود.
- جریان رزرو چهارمرحله‌ای است: `reserve` → `booking` (مهلت‌دار) → `book` → `definite`؛ نگاشتش به قرارداد دومرحله‌ای پورت در `Eghamat24Provider` است.
- تاریخ‌ها بدون منطقهٔ زمانی و به وقت تهران می‌آیند (`grs-time.ts`).
