- [x] اصلاح شد

**محل:** `apps/app/src/app/pages/pay/pay.ts` → `onAmountInput` (همان صفحه‌ای که از دکمهٔ «پرداخت» تب فروشگاه‌ها با `/qr?store=<code>` باز می‌شود).
> ⚠ URL دقیقی که گفتی در پیام نیامده بود؛ فرض بر این صفحه است. اگر منظور فرم «پرداخت حضوری» پنل فروشگاه (`apps/store/src/app/pages/merchant-payment`) بود، آن هم بررسی شود.

**علت ریشه‌ای (پیدا شده):** مبلغ در state به **تومان** نگه داشته می‌شود ولی در input به **ریال** نمایش داده می‌شود. با تایپ اولین رقم، مثلاً `5`:
`Math.floor(5 / 10) = 0` → مبلغ صفر → `input.value = ''`. یعنی هر رقم اول (و هر عدد زیر ۱۰ ریال) پاک می‌شود و کاربر هیچ‌وقت نمی‌تواند شروع به تایپ کند.

**راه‌حل:** مقدار خامِ ریالی را جدا از مبلغ تومانی نگه داریم (یا واحد input را تومان کنیم) و clamp به `wallet.max` روی مقدار ریالی انجام شود. همزمان با مورد ۱۲ (جداکننده سه‌رقمی) پیاده شود تا یک directive مشترک این کار را بکند.

**پذیرش:** تایپ `۵`، `۵۰`، `۵۰۰۰۰` و paste عدد فارسی درست کار کند؛ بیشتر از سقف کیف پول clamp شود؛ caret بعد از فرمت‌شدن نپرد.

## ۷. «ساخت تصویر کد QR ممکن نشد» در پنل فروشگاه — فوری

- [x] علت در build پروداکشن (محلی، Chromium) تأیید شد: قبل از اصلاح خطا، بعد از آن تصویر QR — روی سرور deploy‌شده هنوز چک نشده
- [x] اصلاح شد

**محل:** `apps/store/src/app/pages/qr/qr.ts` → `render()`.

**فرضیهٔ اصلی:** `qrcode` پکیج CommonJS است و با `await import('qrcode')` در build پروداکشن، توابع روی `default` می‌نشینند؛ `QRCode.toDataURL` آن‌جا `undefined` است، `catch` آن را می‌گیرد و فقط پیام عمومی نشان می‌دهد. در dev ممکن است به خاطر interop متفاوت vite سالم باشد — برای همین «همچنان» گزارش می‌شود.

**گام‌ها:**
1. `const mod = await import('qrcode'); const QRCode = mod.default ?? mod;`
2. خطا در `catch` لاگ شود (`console.error`) تا دفعهٔ بعد کور نباشیم.
3. روی build پروداکشن (`pnpm nx build store` و سرو با nginx) تست شود، نه فقط `nx serve`.
4. اگر باز خطا ماند: بررسی CSP در nginx برای `data:` در `img-src`، و اینکه `payload()` (کد فروشگاه) خالی نیست.
