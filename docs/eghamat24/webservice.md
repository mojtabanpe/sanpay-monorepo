# وب‌سرویس اقامت۲۴ (GRS) — محیط تست

اطلاعات این محیط را اقامت۲۴ برای شرکت جهان صنعت پویا سیرجان صادر کرده است.

## محیط‌ها

| چیز             | آدرس                                      |
| --------------- | ----------------------------------------- |
| وب‌سرویس هتل    | `https://hotel-test-01.denv.ir`           |
| پنل داشبورد تست | `https://app.hotel-test-01.denv.ir/login` |
| وب‌سرویس پرواز  | `https://gateway-test-01.denv.ir/flight`  |

> **هر سه فقط از داخل ایران باز هستند.** از بیرون، اتصال TLS وسط دست‌دادن قطع
> می‌شود (`Connection reset by peer`) — دقیقاً مثل محیط دموی هتل‌یار. پس هر چک
> اتصالی باید روی یک شبکهٔ ایرانی اجرا شود.

پشتیبانی فنی: پیام‌رسان **بله**، شناسهٔ `grs_technical_support`.

## اعتبارنامه‌ها

**هیچ‌کدام در گیت نیستند و نباید باشند.** توکن و رمز پنل در `.env` (گیت‌ایگنور)
و در مدیر رمز تیم می‌مانند؛ `.env.example` فقط اسم متغیرها را دارد.

```dotenv
GRS_MODE="live"
GRS_URL="https://hotel-test-01.denv.ir"
GRS_TOKEN="<توکن تستی که اقامت۲۴ داده>"
```

نام کاربری پنل تست یک شمارهٔ موبایل است و رمزش جداگانه داده شده؛ هیچ‌کدام در
کد استفاده نمی‌شوند و فقط برای دیدن رزروها از سمت اقامت۲۴ لازم‌اند.

## احراز هویت

هدر ثابت `Client-Token` روی هر درخواست. نه login، نه session، نه انقضا — یعنی
برخلاف هتل‌یار هیچ منطق تازه‌سازی سشنی لازم نیست.

⚠ توکنی که داده‌اند شکل هش bcrypt دارد ولی **کوتاه‌تر از یک هش کامل است**
(`$2y$12$` + ۲۳ کاراکتر، در حالی که bcrypt ۵۳ کاراکتر بعد از پیشوند دارد). اگر
سرویس ۴۰۳ داد، اولین احتمال این است که متن هنگام کپی بریده شده و باید کاملش را
از پشتیبانی گرفت.

## چک اتصال

```bash
pnpm grs:check
```

سرویس‌های خواندنی را به ترتیب صدا می‌زند (`cities` → `properties` →
`properties/{id}` → `available-rooms` → `suggestion`) و **هیچ رزروی ثبت
نمی‌کند**. با اولین شکست هم متوقف نمی‌شود، چون هدف دومش تأیید مسیرهاست.

## مسیرها — چه چیزی تأیید شده و چه چیزی نه

از داکیومنت GRS Agency API v1.18.4 فقط دو مسیر عیناً آمده است: `GET /v1/cities`
و `POST /v1/book`. باقی مسیرها در `ENDPOINTS` داخل
`apps/api/src/app/tourism/providers/eghamat24/grs-http.client.ts` از روی نام
سرویس‌ها نوشته شده‌اند و با علامت `?` مشخص‌اند.

اولین اجرای `pnpm grs:check` از داخل ایران باید این‌ها را قطعی کند؛ اسکریپت
برای هر ۴۰۴ چند املای جایگزین را هم امتحان می‌کند و اگر یکی جواب داد همان را
پیشنهاد می‌دهد. نتیجه را در `ENDPOINTS` بنویسید — همهٔ مسیرها یک‌جا هستند.

## نکته‌های API که در کد منعکس شده‌اند

- **خطای موجودی با HTTP 200 برمی‌گردد** و فقط در `errors[]` دیده می‌شود؛ پس
  چک‌کردن کد وضعیت کافی نیست (`GrsHttpClient.request` هر دو را می‌بیند).
- **قیمت‌ها ریال‌اند**، در حالی که کل صن‌پی تومان است. تبدیل فقط در
  `eghamat24.mapper.ts` (`rialToToman`) انجام می‌شود.
- جریان رزرو چهارمرحله‌ای است: `reserve` → `booking` (مهلت‌دار) → `book` →
  `definite`؛ نگاشتش به قرارداد دومرحله‌ای پورت در `Eghamat24Provider` است.
- تاریخ‌ها بدون منطقهٔ زمانی و به وقت تهران می‌آیند — `grs-time.ts`.

وقتی فاز خدمات سفر باز شد، دنبال آدرسش نگردیم.
